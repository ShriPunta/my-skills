# shri-skills

Shridhar Puntambekar's collection of agent skills. Each skill is a folder with a `SKILL.md`, optional reference files, and zero-dependency scripts.

Works with Claude Code, Codex, GitHub Copilot CLI, Gemini CLI, Antigravity, Cursor, and any agent that reads [Agent Skills](https://agentskills.io). The skills are plain markdown; the optional index script needs Node 18+, and everything works without it.

## Install

Pick one route per agent. A plugin install and a copied install side by side give you every skill twice.

**Claude Code**

```
/plugin marketplace add ShriPunta/my-skills
/plugin install shri-skills@shripunta
```

**Codex**

```sh
codex plugin marketplace add ShriPunta/my-skills
codex plugin add shri-skills@shripunta
```

Codex reads `.claude-plugin/` as a fallback marketplace manifest. Alternatively, use the manual route below; Codex loads skills from `~/.agents/skills/`.

**GitHub Copilot CLI**

```sh
copilot plugin marketplace add ShriPunta/my-skills
copilot plugin install shri-skills@shripunta
```

**Gemini CLI**

```sh
gemini skills install https://github.com/ShriPunta/my-skills.git --path skills/engineering
```

**Antigravity**

```sh
git clone https://github.com/ShriPunta/my-skills.git
mkdir -p ~/.gemini/antigravity/skills
for s in repo-overview setup-repo-overview analyze-pr; do
  ln -s "$PWD/my-skills/skills/engineering/$s" ~/.gemini/antigravity/skills/$s
done
```

That path is global. For one workspace, link into `<workspace>/.agent/skills/` instead. Or run `npx skills@latest add ShriPunta/my-skills` and choose Antigravity.

**Any other agent** (via [skills](https://www.npmjs.com/package/skills); choose your agent when asked):

```sh
npx skills@latest add ShriPunta/my-skills
```

**Manual** (symlink into your agents' skills folders; keep `repo-overview` and `setup-repo-overview` side by side, since setup copies files from its sibling):

```sh
git clone https://github.com/ShriPunta/my-skills.git
mkdir -p ~/.claude/skills ~/.agents/skills
for s in repo-overview setup-repo-overview analyze-pr; do
  ln -s "$PWD/my-skills/skills/engineering/$s" ~/.claude/skills/$s
  ln -s "$PWD/my-skills/skills/engineering/$s" ~/.agents/skills/$s
done
```

## Skills

### User-invoked

Start these yourself: the slash command in Claude Code, or your agent's skill menu. Harnesses that honour the user-only flag (Claude Code, Codex) never run them on their own.

- [setup-repo-overview](skills/engineering/setup-repo-overview/SKILL.md) ([docs](docs/engineering/setup-repo-overview.md)): one-time setup for `repo-overview`: preset, location, optional index script, hooks or CI, and an agent pointer line (`/setup-repo-overview` in Claude Code).
- [analyze-pr](skills/engineering/analyze-pr/SKILL.md) ([docs](docs/engineering/analyze-pr.md)): analyzes a PR or MR on GitHub, GitLab, Bitbucket, Azure DevOps, Gitea, or Forgejo into a by-area summary and follow-up list, then refreshes generated files and docs on its branch (hands overview updates to `repo-overview`); posts, commits, and pushes only on your yes (`/analyze-pr` in Claude Code).

### Model-invoked

The agent reaches for these when your request matches.

- [repo-overview](skills/engineering/repo-overview/SKILL.md) ([docs](docs/engineering/repo-overview.md)): keeps a modular repo overview (summary, author intent, optional sections, item groups, `INDEX.md` router) current as features land and before each PR.

**How they fit:** run `setup-repo-overview` once; `repo-overview` keeps the overview current before each PR; run the analyze-pr skill (`/analyze-pr` in Claude Code) on a PR, and it calls `repo-overview` for overview updates.

## repo-overview at a glance

Run the setup-repo-overview skill once (`/setup-repo-overview` in Claude Code); it hands off to `repo-overview`, which builds the overview. After that, the agent updates it when a feature is done or a PR is next. Setup picks a **preset**: lite, app, library, monorepo, platform, docs, or ml, plus modifiers template, fork, oss, regulated, and large. A script, dotfiles repo, or side project gets a two-file **lite** overview; a product gets the full set.

The agent derives facts from the code and asks you only for intent: why it exists, what success looks like, what is out of scope. Anything you skip stays a visible `TODO(author):` line; the agent never guesses intent. A full `app` overview:

```
docs/overview/
  INDEX.md                  # agents read this first
  overview.config.json
  00-summary.md             # what it is, who for, status, how to run
  01-intent.md              # why, goals, principles, non-goals (author-owned)
  02-stack.md
  03-operations.md
  roadmap.md
  features/
    _template.md
    billing.md
    auth.md
scripts/overview-index.mjs  # optional zero-dep Node script: write, --check, --validate, --stale --base
```

Sample `INDEX.md`:

```markdown
<!-- GENERATED by overview-index.mjs. Do not edit by hand; regenerate with the repo's overview script. -->

# Acme Overview

Read this first, then open only the files you need. Paths are relative to this folder.

## Core

- `00-summary.md`: Acme is a self-hosted invoicing app for freelancers. _(overview, start-here)_
- `01-intent.md`: Why Acme exists, what success looks like, and what is out of scope. _(intent, goals, non-goals)_

## Features

- `features/auth.md`: `platform` · `Implemented` · Email and Google sign-in with session cookies. _(login, oauth, sessions)_
- `features/billing.md`: `payments` · `In progress` · Stripe checkout and recurring invoices. _(stripe, invoices, tax)_
```

`--stale --base origin/main` lists docs whose `paths` changed on the branch while the doc did not, plus author docs due for reconfirmation; the pointer line has agents run it before each PR, and the agent edits only docs whose change a reader should know about (features, architecture, stack, operations, intent), at a high level. In CI, `--check` gates and `--stale` reports; add `--strict` to gate on staleness. Without Node, the agent maintains `INDEX.md` by hand in the same format and uses `git diff` for staleness. Hook and CI snippets: [HOOKS.md](skills/engineering/setup-repo-overview/HOOKS.md).
